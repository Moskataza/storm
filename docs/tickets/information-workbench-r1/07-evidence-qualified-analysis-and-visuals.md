# T07: Produce evidence-qualified analysis and trustworthy visuals

## Parent

[Information Workbench R1 specification](https://github.com/Moskataza/storm/issues/1)

## What to build

A task turns saved source material and structured data into findings, comparisons, and charts that answer the worksheet's questions. The report makes the evidence, source type, calculations, disagreements, and uncertainty inspectable. This slice uses fixture-backed task inputs independently of live service availability.

## Acceptance criteria

- [ ] Findings link to source evidence spans or recorded calculations; claims, experiences, opinions, identifiable promotions, calculated results, and unknown sponsorship remain distinguishable.
- [ ] Contradictory fixture sources yield explicit disagreement and qualified conclusions; unsupported synthesis is withheld or clearly qualified.
- [ ] Duplicate/derived captures retain lineage and do not become independent confirmations. Likes/views remain contextual signals.
- [ ] Numeric results match controlled input fixtures and preserve periods, dates, units/currency, inputs, and methods. Missing values remain missing and incompatible quantities are identified.
- [ ] Appropriate browser tables/charts use stored structured results. Sparse evidence produces an honest report without invented numeric visuals.
- [ ] The report starts with findings related to the requester's purpose and provides expandable supporting evidence, methods, and limitations.
- [ ] Financial and AI-market fixtures use the same workflow and findings model; social sample observations remain distinct from market-wide estimates.
- [ ] High-level workflow assertions cover contradictions, provenance, numeric values, absent evidence, and same-report revision semantics rather than exact generated phrasing.
